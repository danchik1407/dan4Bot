# Почему в аппке 0, а в «кармане» 42 000

## 1. Что показывала аппка
`loadUserData()` при любой ошибке (`!response.ok`, 500, таймаут Render) **молча** выходил,
`balance` оставался `0`, а `updateUI()` рисовал этот ноль в шапке, профиле и всех играх.
То есть «0» — это не данные из базы, а «данные не пришли». Бот же читает ту же таблицу
`users` напрямую через `supabase` — поэтому в «кармане» цифра правильная.

## 2. Что могло валить /api/user (найдено в коде)
| Причина | Как проявлялась |
|---|---|
| `int(db_user.get("keys"))` при `keys = NULL` | TypeError → 500 → аппка рисует 0 |
| `int(db_user.get("last_chest"))` при `NULL` | то же |
| `json.loads(inventory)` когда колонка jsonb (уже список) | TypeError → 500 |
| строка сохранена с `user_id` текстом, а `.eq("user_id", int)` | Supabase отвечает пустым списком → аппка создаёт **новую** строку с 0 коинов и показывает её |
| дубли строк в `users` | читалась «не та» строка (нулевая) |
| холодный старт Render / 502 / обрыв | fetch падал, ретраев не было |

Всё это исправлено на сервере (устойчивое чтение, поиск строки и по int, и по тексту,
выбор строки с реальным балансом, `503` вместо `500`) и на клиенте
(«…» вместо ложного нуля, 3 ретрая, баннер с причиной, кнопка «Повторить»).

## 3. Как проверить свой аккаунт за 10 секунд
Открой на телефоне (подставь свой initData сложно, поэтому проще):

1. Обнови мини-аппку (после деплоя) — под шапкой появится баннер с причиной, если что-то не так.
2. Тап по балансу в шапке (или по цифре в профиле) = повторная синхронизация.
3. Для точной диагностики сервер отдаёт `POST /api/self_check` с `{"initData": "<твой initData>"}`
   — он вернёт `rows_found`, сырые `coins_raw`, `created_at_present` и готовый профиль.

Пример запуска из консоли браузера внутри мини-аппки:

```js
fetch('https://aura-api-mptt.onrender.com/api/self_check', {
  method: 'POST', headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ initData: window.Telegram.WebApp.initData })
}).then(r => r.json()).then(console.log);
```

Что означает ответ:
- `"ok": false, "stage": "verify"` — `initData` не проходит проверку: на сервере другой `BOT_TOKEN`.
- `"rows_found": 0` — строки с таким `user_id` нет: значит id в базе другой (старый бот писал иначе).
- `"rows_found": 2` и одна строка с `coins: 0` — дубли; теперь сервер берёт строку с деньгами.
- `"ok": true, "row": { "coins": 42000 }` — сервер видит деньги; значит проблема была только в клиенте (сеть).

## 4. SQL-проверка (если хочется посмотреть в Supabase)
```sql
select id, user_id, pg_typeof(user_id) as id_type, coins, keys, last_chest, created_at
from users
where user_id::text = 'ТВОЙ_USER_ID';
```
- `id_type = text` — старый формат, теперь сервер его тоже находит (но лучше привести к bigint).
- две строки — дубли, сервер берёт ту, где больше коинов.
- `coins = NULL` — сервер отдаст 0; поправить: `update users set coins = 0 where coins is null;`
