# ============================================================================
#  Задача 41: почему деплой на Render падал («Failed») и что тут важно.
# ----------------------------------------------------------------------------
#  На Render сервис dan4Bot собирался на Python 3.14 и падал ЕЩЁ НА СБОРКЕ:
#      pydantic-core 2.27.2 ... building from source ...
#      aiohttp 3.11.18  ... building from source ...
#  Причина: старый пин aiogram<3.20 тянет pydantic<2.11 и aiohttp<3.12,
#  а у этих версий НЕТ готовых колёс (wheel) под cp314. pip пытается собрать
#  их из исходников, и сборка обрывается — новый код не доезжает до сервера,
#  в проде остаётся старый bot.py с падением strip_prefix(None).
#
#  Решение: диапазон, который разрешается в версии с колёсами И под 3.14,
#  И под 3.11 (на 3.11 Render может остаться, если PYTHON_VERSION задан):
#      aiogram 3.31  → pydantic 2.12+ (pydantic-core 2.41: cp311 + cp314)
#                    → aiohttp 3.13+ (cp311 + cp314)
#  Верхняя граница <3.32 — осознанно: 3.32/3.33 на Python 3.11 падают при
#  импорте (`TypeError: unhashable type: 'FailFast'` в typing.Union),
#  а нам нужна совместимость с обеими версиями интерпретатора.
# ============================================================================
aiogram>=3.22,<3.32
python-dotenv>=1.0.0
# aiohttp тянет aiogram, но фиксируем явно: именно его сборка из исходников
# ломала деплой на Python 3.14.
aiohttp>=3.13,<3.15
supabase
fastapi
uvicorn
# aura-api ставит httpx вместе с supabase; aiohttp нужен боту (aiogram).
httpx>=0.26
